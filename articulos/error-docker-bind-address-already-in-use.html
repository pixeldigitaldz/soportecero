Error: Error starting userland proxy: bind: address already in use en Docker

El Diagnóstico Rápido

Causa
Otro servicio usa el puerto (ej. Nginx/Apache)
Solución
Detener el servicio o cambiar el puerto en Docker (docker-compose.yml)
Causa
Contenedor zombi reteniendo el puerto
Solución
Reiniciar el servicio de Docker o matar el proceso
Causa
Conflicto con Docker Desktop (Windows/Mac)
Solución
Reiniciar Docker Desktop o WSL2

La Solución Paso a Paso

Encuentra qué proceso está usando el puerto En Linux, ejecuta el siguiente comando para ver qué aplicación está ocupando el puerto (cambia 80 por tu puerto en conflicto):

BASH 
sudo netstat -tulpn | grep :80

O usando lsof:

BASH 
sudo lsof -i :80

Detén el servicio conflictivo Si descubres que Apache o Nginx están corriendo nativamente y ocupando el puerto 80, detenlos:

BASH 
sudo systemctl stop apache2
sudo systemctl disable apache2

Mata el proceso si es necesario Si es un proceso zombi, puedes matarlo usando su PID (el número que te dio el comando anterior):

BASH 
sudo kill -9 <PID>

Cambia el puerto en tu Docker Compose Si no puedes detener el servicio nativo, simplemente cambia el puerto que expone Docker editando tu docker-compose.yml:

YAML 
ports:
  - "8080:80" # Cambia el puerto izquierdo (host)

Luego vuelve a levantar el contenedor:

BASH 
docker-compose up -d

Consejo de Prevención

Prácticas de seguridad recomendadas:

  • Asignación de puertos: Usa un proxy inverso como Traefik o Nginx Proxy Manager en los puertos 80/443 y expón el resto de contenedores de forma interna.
  • Monitoreo: Revisa qué puertos están en uso en tu servidor antes de desplegar un nuevo stack usando netstat o ss.
  • Limpieza regular: Ejecuta docker system prune para limpiar redes y contenedores huérfanos que podrían estar bloqueando recursos.
