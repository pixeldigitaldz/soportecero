The error **`Could not resolve host: google.com`** or **`Temporary failure in name resolution`** running `ping`, `apt update`, or `curl` on Linux servers (Ubuntu, Debian, CentOS) occurs when the local DNS resolution daemon (**`systemd-resolved`**) or the symlink file `/etc/resolv.conf` is broken or misconfigured.

> **Quick Solution (1 Minute):**
> 1. Set a temporary public DNS resolver in `/etc/resolv.conf`:
>    `echo "nameserver 8.8.8.8" | sudo tee /etc/resolv.conf`
> 2. Restart local DNS resolver daemon:
>    `sudo systemctl restart systemd-resolved`

## 🚀 Step-by-Step Fixes

### Step 1: Verify `systemd-resolved` Daemon
Ensure systemd's local DNS resolution service is active:

```bash
sudo systemctl status systemd-resolved
```
If disabled or stopped, enable and start it:
```bash
sudo systemctl enable --now systemd-resolved
```

### Step 2: Rebuild `/etc/resolv.conf` Symlink
On modern Linux OS releases, `/etc/resolv.conf` MUST be a symbolic link pointing to the file generated by systemd. If overwritten by a broken static file:

```bash
# 1. Remove broken resolv.conf
sudo rm -f /etc/resolv.conf

# 2. Re-create symlink to systemd stub resolver
sudo ln -s /run/systemd/resolve/stub-resolv.conf /etc/resolv.conf

# 3. Restart DNS resolution service
sudo systemctl restart systemd-resolved
```

### Step 3: Configure Static DNS in Netplan
Prevent cloud provider DHCP leases from overwriting working DNS servers upon reboot:

Edit `/etc/netplan/50-cloud-init.yaml`:
```yaml
network:
  version: 2
  ethernets:
    eth0:
      nameservers:
        addresses: [8.8.8.8, 1.1.1.1]
```
Apply configuration: `sudo netplan apply`.
